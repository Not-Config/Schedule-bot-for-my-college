# Schedule Bot

Telegram-бот с расписанием Липецкого колледжа. Бот самостоятельно входит в личный кабинет, получает расписание всех настроенных групп и обновляет локальный кеш без перезапуска.

## Что теперь работает автоматически

- обновление расписания при запуске и затем каждые 6 часов с переключателем в админ-панели;
- автоматические и ручные резервные копии расписания с восстановлением;
- прямое получение таблицы через `/ajax.handler.php`: Playwright нужен только для обнаружения актуальных ID семестра и группы;
- кеш обнаруженных ID с автоматическим повторным определением, если колледж их поменял;
- до трёх повторных попыток для каждой группы при временной ошибке сайта;
- фоновая загрузка: бот отвечает пользователям, пока идёт обновление;
- безопасная атомарная запись — неудачное обновление не уничтожает старое расписание;
- мгновенная перезагрузка данных в памяти после успешного получения;
- работа через локальный Telegram Bot API или через официальный API;
- ручное обновление из админ-панели и командой `/update`;
- самостоятельное добавление новой группы при регистрации через проверку аккаунта ЛК;
- пользовательский профиль с просмотром и изменением личной привязки ЛГТУ;
- сохранение расписания и базы данных в Docker volumes.

## Быстрый запуск через Docker Compose

Требуются Docker и Docker Compose. Локальный Telegram Bot API должен быть уже запущен — этот репозиторий его не дублирует.

```bash
git clone https://github.com/Not-Config/Schedule-bot-for-my-college.git
cd Schedule-bot-for-my-college
cp .env.example .env
nano .env
docker compose up -d --build
docker compose logs -f bot
```

Обязательно заполните в `.env`:

- `BOT_TOKEN` — токен бота;
- `SCHEDULE_ACCOUNTS_JSON` — логин и пароль кабинета для каждой группы;
- `DB_PASSWORD` и `DB_ROOT_PASSWORD` — новые пароли MariaDB.

Если локальный Bot API слушает порт `8081` на том же Linux-сервере, оставьте:

```dotenv
BOT_API_BASE_URL=http://host.docker.internal:8081
BOT_API_IS_LOCAL=true
```

Если бот и Bot API находятся в одной Docker-сети, вместо адреса хоста укажите имя сервиса, например `http://telegram-bot-api:8081`, и подключите контейнер бота к этой сети. Чтобы временно вернуться к официальному API Telegram, оставьте `BOT_API_BASE_URL` пустым.

## Настройка автообновления

Основные переменные:

| Переменная | Значение по умолчанию | Назначение |
|---|---:|---|
| `SCHEDULE_AUTO_UPDATE_ENABLED` | `true` | состояние автообновления до первого переключения в админ-панели |
| `SCHEDULE_UPDATE_ON_STARTUP` | `true` | обновить расписание сразу после запуска |
| `SCHEDULE_UPDATE_INTERVAL_MINUTES` | `360` | интервал фонового обновления |
| `SCHEDULE_UPDATE_MAX_ATTEMPTS` | `3` | число попыток на одну группу |
| `SCHEDULE_UPDATE_RETRY_SECONDS` | `10` | базовая пауза между попытками |
| `SCHEDULE_PAGE_TIMEOUT_SECONDS` | `35` | тайм-аут страниц и AJAX-ответа |
| `SCHEDULE_BACKUP_LIMIT` | `10` | сколько последних резервных копий хранить |
| `SCHEDULE_SOURCE_CACHE_FILE` | `data/schedule-source-cache.json` | кеш ID семестра и группы без секретов |
| `SCHEDULE_BROWSER` | `chromium` | браузер Playwright |
| `SCHEDULE_HEADLESS` | `true` | запуск браузера без окна |
| `BOT_TIMEZONE` | `Europe/Moscow` | часовой пояс расписания |

### Одноразовый recovery-monitor

Если авторизация ЛК временно сломана, можно включить щадящий монитор одной
приоритетной группы:

```dotenv
SCHEDULE_RECOVERY_ENABLED=true
SCHEDULE_RECOVERY_GROUP=Т9-ИП-24-1
SCHEDULE_RECOVERY_INTERVAL_MINUTES=5
SCHEDULE_RECOVERY_JITTER_SECONDS=45
SCHEDULE_RECOVERY_HTTP_TIMEOUT_SECONDS=20
```

Монитор делает одну лёгкую AJAX-попытку входа за запуск. Пока вход не работает,
Playwright не запускается и обычное обновление остальных групп откладывается.
При первом ответе с `REDIRECT_URL` бот переносит PHP-сессию в браузер, перехватывает
точный запрос и сырой ответ `/ajax.handler.php`, обновляет только выбранную группу
поверх существующего кеша и прекращает сетевые попытки. Расписание других групп
не удаляется.

Диагностический захват сохраняется с правами `0600` в
`data/recovery-captures/`, а `data/recovery-state.json` отмечает успешное
завершение. Cookies и пароли в захват не записываются. Чтобы вручную запустить
одноразовый монитор повторно, остановите бота и удалите только
`data/recovery-state.json`, затем снова запустите сервис.

Интервал меньше пяти минут намеренно не допускается, чтобы не нагружать сайт колледжа.

После первого успешного обнаружения бот сохраняет только адрес AJAX и значения
`semester/group` в `data/schedule-source-cache.json`. Логины, пароли и cookies
туда не попадают. Следующие обновления выполняются обычными HTTP-запросами без
запуска браузера. Если URL семестра или ID перестали работать, кеш считается
устаревшим, Playwright один раз заново перехватывает параметры, после чего бот
снова возвращается к прямому AJAX.

Названия дисциплин, которые сайт прислал целиком заглавными буквами, автоматически
приводятся к нормальному виду. Известные сокращения (`ЛГТУ`, `ОС`, `SQL`,
`Linux` и другие) при этом сохраняются.

Аккаунты передаются одним JSON-объектом:

```dotenv
SCHEDULE_ACCOUNTS_JSON='{"Т9-ИП-24-1":{"login":"login1","password":"password1"},"Т9-ИП-24-2":{"login":"login2","password":"password2"}}'
```

Не добавляйте `.env` в Git — файл уже находится в `.gitignore`.

При регистрации пользователь может нажать «➕ Добавить свою группу», отправить логин и пароль от ЛК и дождаться проверки. Бот удаляет сообщения с учётными данными из личного чата, определяет группу по странице кабинета, получает её расписание и регистрирует пользователя. После проверки в разделе «👤 Профиль» показываются личный логин ЛГТУ и обнаруженная группа; пароль в профиль и таблицу привязок не записывается. Привязку можно повторно проверить и заменить из профиля.

Если группа новая, рабочий аккаунт для обновления её расписания сохраняется отдельно в `data/accounts.json` с правами `0600`; этот файл подключён к постоянному Docker volume. Для уже настроенной группы повторная копия пароля не сохраняется.

Файл `data/accounts.json` содержит рабочие пароли от ЛК: не публикуйте его, не добавляйте в Git и включайте в защищённые резервные копии.

## База данных

При обычном `docker compose up` запускается MariaDB, а таблицы из `schema.sql` создаются при первом старте. Таблица персональных привязок `college_account_links` также безопасно создаётся самим ботом при обновлении существующей установки. Старую внешнюю MySQL/MariaDB тоже можно использовать: задайте `DB_HOST`, `DB_PORT`, `DB_NAME`, `DB_USER`, `DB_PASSWORD`, примените `schema.sql` и запустите только бота:

```bash
docker compose up -d --build --no-deps bot
```

Администраторов можно указать массивом Telegram ID в `settings/global.json`. Поле `is_admin` в базе также поддерживается.

В админ-панели доступны глобальные оповещения и рассылки выбранной учебной группе. Администратор выбирает аудиторию, отправляет текст, фото, видео, документ или другое обычное сообщение Telegram, подтверждает рассылку и получает статистику доставки. Сообщение копируется подходящим зарегистрированным пользователям с ограничением скорости. Пользователи, для которых Telegram возвращает блокировку бота, автоматически удаляются из базы вместе с настройками; временные ошибки доставки к удалению не приводят.

Там же можно включать и выключать автообновление, создавать резервные копии вручную, просматривать последние копии и восстанавливать выбранную. Перед каждым успешным обновлением, добавлением группы и восстановлением текущая версия сохраняется автоматически. В копии входят только расписание и эталон недели — без аккаунтов ЛК.

## Как хранится расписание

`settings/schedule.json` используется как начальный резервный кеш. Свежие данные записываются в `data/schedule.json`, дата и цвет эталонной недели — в `data/reference.json`, аккаунты добавленных пользователями групп — в `data/accounts.json`, обнаруженные ID источника — в `data/schedule-source-cache.json`, runtime-переключатели — в `data/runtime-settings.json`, резервные копии — в `data/backups/`. В Docker каталог `data` подключён к постоянному volume.

Если сайт временно недоступен, бот пишет ошибку в лог и продолжает показывать последний успешно полученный вариант. Следующая попытка произойдёт автоматически.

## Журнал посещаемости (экспериментальная функция)

После запуска бот сам создаёт новые таблицы MariaDB. Кнопка **«Посещаемость»**
появится в главном меню, также доступна команда /attendance. Существующие
таблицы расписания и пользователей не заменяются.

Для запуска нужна привязка *личного* аккаунта ЛК через раздел «Профиль».
Один только выбор группы в настройках не даёт доступа к журналу.

### Загрузка списка студентов

Если для группы уже настроен аккаунт ЛК (как для получения расписания),
администратор может выполнить в личном чате:

    /attendance_sync Т9-ИП-24-1

Бот один раз авторизуется существующим механизмом и отправит запрос
POST /ajax.handler.php с полями search_person=1, type="", value=<группа>.
Данные группы попадут только в MariaDB. Автоматическая фоновая синхронизация
пока не включена. Выдача поиска может оказаться неполной, поэтому не найденные
записи не удаляются. Если кабинет не отвечает, есть ручной импорт ниже.

Сохрани ответ POST-запроса /ajax.handler.php с поиском студентов по группе
как обычный UTF-8 HTML/TXT-файл (не HAR: в нём могут быть cookies).
В личном чате администратора отправь этот файл боту, затем ответь
**на сообщение с файлом** командой:

    /attendance_import Т9-ИП-24-1

Импортируются только карточки с data-student, корректным data-person и
совпадающей группой. Извлекаются только ФИО, ID и группа; аватары, переписка
и сведения авторизации не сохраняются. Повторный импорт обновляет записи.
**Неполный ответ поиска не удаляет отсутствующих в нём студентов.**
Не загружай реальные списки студентов в публичный репозиторий.

### Староста и подтверждение личности

Администратор назначает старосту после проверки его аккаунта:

    /attendance_starosta 123456789

Снять права старосты или ошибочную подтверждённую привязку можно командами:

    /attendance_unstarosta 123456789
    /attendance_unlink 123456789

Здесь используется числовой **Telegram ID** (отображается в профиле бота).
Права действуют только для группы, привязанной к аккаунту старосты в ЛК.
Студент выбирает себя в списке и отправляет заявку. Староста или
администратор видит заявки в меню «Посещаемость → Заявки» и подтверждает
после независимой проверки личности; староста не может подтвердить себя.
Один student/person ID может быть закреплён только за одним Telegram.
Если студент сменит привязанный аккаунт ЛК, старая привязка к журналу
перестанет подходить, пока её не подтвердят заново.

### Отметки и статистика

Студент может самостоятельно поставить «Присутствую» только в интервале от
15 минут до начала пары до 15 минут после её окончания. Самоотметка
не считается доказательством физического присутствия. После первой
отметки студент не может перезаписать оценку старосты.

Староста управляет статусами: присутствует, опоздал, отсутствует,
уважительная причина. При закрытии журнала неотмеченные студенты получают
статус «отсутствует». Каждое изменение с предыдущим и новым статусом,
Telegram ID автора и временем записывается в attendance_events.
После закрытия староста может исправлять ошибки, они также аудируются.

Статистика учитывает присутствие и опоздания как посещённые пары.
Уважительные причины и ещё не проставленные отметки не попадают
в знаменатель. Пока записей нет, процент показывается как «н/д».

Ограничения первой версии: синхронизация списка выполняется по команде
администратора (или через HTML-файл), без фонового таймера; роль старосты
назначается администратором. Автоматически доказать нахождение студента
в аудитории нельзя. Журнал доступен только в личном чате с ботом.

## Telegram Mini App — кнопки в веб-приложении

Добавлен мобильный интерфейс `webapp/` с разделами **Расписание**,
**Посещаемость**, **Статистика** и **Профиль**. Он использует
существующую MariaDB и правила журнала.

- Студент выбирает пару и нажимает «Я присутствую на паре» в разрешённое время.
- Если личность ещё не подтверждена, кнопка «Выбрать своё ФИО» отправляет заявку.
- Староста видит список группы, четыре статуса, закрытие журнала и заявки.
- Личная статистика видна студенту; вся группа — только старосте/администратору.
- Приложение не запрашивает пароль ЛК. Требуется уже проверенная привязка в боте.
- Backend проверяет подпись и срок Telegram `initData`, группу и роль на каждом API-запросе.

### Включение (по умолчанию выключено)

Нужен отдельный HTTPS-адрес с reverse proxy на локальный порт 8092.
Не публикуйте Python API напрямую по HTTP.

Добавьте в `.env`:

```dotenv
ATTENDANCE_WEBAPP_URL=https://schedule.example.ru
ATTENDANCE_WEBAPP_PORT=8092
```

Замените `schedule.example.ru` своим доменом с действительным TLS.
Пример Caddy на том же хосте, где работает Docker Compose:

```caddyfile
schedule.example.ru {
    reverse_proxy 127.0.0.1:8092
}
```

`docker-compose.yml` привязывает порт только к `127.0.0.1` хоста.
Внутри Docker контейнера `ATTENDANCE_WEBAPP_BIND=0.0.0.0`,
для системного запуска вне Docker используется `127.0.0.1`.

После запуска HTTPS и бота в главном меню появится кнопка
**«Веб-приложение»**, открывающая интерфейс внутри Telegram.
Старые Telegram-кнопки и команда `/attendance` останутся доступны.

В обычном браузере HTML отображается, но API требует подписанный Telegram
`initData`, который появляется только при запуске Mini App через Telegram.

Перед подключением к рабочему боту протестируйте новую схему MariaDB,
временные ограничения, подтверждение личности, права старосты и прокси.
Основная ветка `master` и сервер не меняются автоматически.
